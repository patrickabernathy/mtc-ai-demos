Cut the bakery into components

This starter is lab 1, finished for you — every pastry already works, the cart already works. Nothing on screen is broken tonight. Your job is to take one honest, working, 260-line file and turn it into pieces without breaking any of it.

1. Run it, and confirm it already works

npm install
npm run dev

Open http://localhost:3000. Change quantities, add pastries, remove them, watch the total. If anything is broken, that's a bug in this starter — flag it, don't work around it.

Know what you're starting from. Open app/page.tsx. It's one component, five useState calls for quantities, one useState for the cart, and markup for five pastries typed out by hand — recognize it, it's what lab 1 asked you to build.

2. Why split it up at all

The page works. That's not the problem. The problem is that it's one file doing five jobs, and finding "the part that draws a cart line" means scrolling past four other things first. Splitting it up doesn't change what the page does — only where the code that does it lives.

AI hint — before you start moving code. If "component" and "props" are still fuzzy, ask something like:

"I have one big React function that renders a whole page. What's the actual benefit of splitting it into smaller components, beyond 'it's tidier'? What does a prop let a component do that it couldn't do before?"

You want the conceptual answer before you start cutting, so you can tell, file by file, whether what you just built matches it.

  // ...the five pastries, moved from page.tsx...

The cart does not go in this file — it's state, it changes, it has to stay in a component. Only the menu, which never changes, belongs to a plain data file.

Stop and check. Five MenuItems should render exactly the five pastries you had before, pulled from menu instead of typed five times. Nothing has to click yet. If the layout matches page.tsx before you deleted it, you're on track.

5. Now make the cart flow through props — the actual lesson

Two different components need the cart: MenuList adds to it, CartList shows it. Neither one owns it. So the cart state has to live in the one place that's above both of them: page.tsx.

Required. In page.tsx:

  1. Keep "use client" and the cart useState there — delete everything else that used to be markup.
  2. Write handleAdd(item, qty) and handleRemove(name) there, same logic you already wrote in lab 1.
  3. Pass them down: <MenuList onAdd={handleAdd} /> and <CartList cart={cart} onRemove={handleRemove} />.
  4. MenuList doesn't call onAdd itself — it just hands it further down to each MenuItem.

AI hint. This is the step people get stuck on, and the stuck feeling is usually "which component should own this state?" — not a syntax error. A useful prompt names the actual components:

"I have a MenuList component and a CartList component, and both need access to the same cart array. Where should that state live, and how do child components change state that lives in a parent?"

If the answer uses the phrase "lifting state up," that's the name for what you're doing. Look it up by that name too — it's a standard term, not something specific to this class.

What stays local — MenuItem's own quantity

The quantity on one pastry card is not shared with anyone. Nobody outside that card needs to know what it's currently set to until the moment Add to cart is clicked. Required. Give MenuItem its own useState for qty, and call onAdd(item, qty) when its own button is clicked.

Expect this one. If you also tried to lift qty up to page.tsx "to be safe," you now have five numbers living in the one component that only one card at a time actually reads. Watch for the tell: a piece of state that only ever gets used by the component right next to where you defined it doesn't need to travel anywhere.

6. Optional, if you finish early

  • Add an item count to Header — it doesn't take props yet, so you'll have to give it one and pass the number down from page.tsx.

AI hint — going deeper. Once it all works, this is worth understanding by name:

"What's the difference between 'data flows down' and 'events flow up' in React? Use my MenuItem → MenuList → page.tsx chain as the example."

That sentence is the entire mental model for every React app you'll build after this one. It's worth being able to say it back without notes.

What "done" looks like

  • The page at localhost:3000 behaves exactly like the lab 1 starter did — nothing changed on screen.
  • There are five files in components/, none of them longer than the original single file's worth for that piece.
  • The menu lives in types/coffee.ts. The cart does not — it's state, in page.tsx.
  • MenuItem owns its own quantity. page.tsx owns the cart. Nothing owns both.
  • npm run build finishes with no errors.
