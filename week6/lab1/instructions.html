Give the bakery page state

Ridgeline Bakery is on screen and it is doing nothing. Every quantity says 1 forever, every cart is the same two lines, and every button is painted on. Tonight you give it a memory — nothing leaves this one file.

1. Run it

npm install
npm run dev

Open http://localhost:3000. Five pastries, a cart with two lines already in it, a total. Click anything. Nothing moves. That's today's whole problem.

2. Read app/page.tsx before you touch it

Everything is in one file, on purpose — a menu array, a cart array, and markup for all five pastries typed out by hand. Find these three things before you write anything:

  • The const cart = [...] near the top. That's plain data. Nothing watches it.
  • The <span className="qty">1</span> inside the Croissant card. Hard-coded.
  • Every button — qty-btn, add-btn, remove-btn — has no onClick at all.

AI hint — before you write a line of code. If "state" is still an abstract word, ask your assistant something like:

"I have a number shown on a web page, and a button that's supposed to change it. Why doesn't just reassigning the JavaScript variable make the page update? What is React state actually for?"

Read the answer, close the chat, and come back. The goal tonight is that you can explain that answer to someone else — not that the chat window has it open next to your editor the whole time.

3. Make one pastry work, start to finish

Required. Pick Croissant. In order:

  1. Put "use client"; on the very first line of the file. A page with an onClick has to run in the browser, not just on the server that builds it.
  2. Import useState from react.
  3. Give Croissant its own piece of state, starting at 1, and show that state instead of the hard-coded 1.
  4. Wire the - and + buttons to change it. Don't let it go below 1 — nobody orders zero croissants.

Stop and check. Click Croissant's + a few times. The number on screen should climb. If it doesn't, you likely changed the variable but never called the set... function — that call is the only thing that tells React to redraw.

4. Make Croissant's Add to cart button do something real

Right now cart is a const array sitting above the component. Required. Turn it into state too — it has to change, so it has to be state, same reasoning as step 3.

Then wire Croissant's Add to cart button to put a line into that cart state, using however many croissants the quantity control currently shows. Two cases to handle, and both are things a real cart does:

  • Croissant isn't in the cart yet → add a new line for it.
  • Croissant is already in the cart → increase that line's quantity instead of adding a second line.

Expect this one. It is tempting to write cart.push({ ... }) and move on. The array really does grow — and the screen never updates. React only repaints when you hand a set... function a new array or object, not when you edit the old one in place. If you get stuck here, that's almost certainly why.

AI hint. If you've read that warning and are still stuck on why your cart isn't updating, a good next prompt is narrow and shows your actual code, not a request for the answer:

"Here's my setCart call: [paste it]. The array changes when I log it, but the screen doesn't update. What's wrong?"

Pasting your real code gets a useful answer. Asking "why isn't my cart working" gets a generic essay about React you'll have to re-translate back onto your file anyway.

Now wire the Remove button on Croissant's cart line (if it's in the cart) so it takes that line back out.

5. Do the other four pastries

Cinnamon Roll, Sourdough Loaf, Blueberry Muffin, Baguette. Same three things each: its own quantity state, its own wired +/-, its own Add to cart calling the same cart-update logic you already wrote for Croissant.

This is supposed to feel bad. By the time you finish Baguette you will have five nearly identical useState calls and five nearly identical onClick handlers. That repetition isn't a sign you're doing it wrong — it's the whole reason lab 2 exists. Feel it here first.

6. Optional, if you finish early

  • Add a Clear cart button that empties the cart in one click.
  • Show the number of items in the cart somewhere in the header.
  • Cap each quantity at some maximum (say 12) and grey out the + button when it's reached.

AI hint — going deeper. Once the lab works, it's worth asking why the fix in step 4 mattered, not just that it did:

"Explain why React needs a new array reference to detect a change, instead of just checking whether the array's contents are different."

That question is about to matter again in lab 2, where the same array gets passed between three different components.

What "done" looks like

  • Every pastry's +/- changes its own displayed quantity, and never goes below 1.
  • Every Add to cart adds a line, or increases an existing line's quantity.
  • Every Remove takes a line out of the cart.
  • The total at the bottom is always correct, for every combination you can click together.
  • Everything still lives in app/page.tsx. No new files.
