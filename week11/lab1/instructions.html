Happy Tails: a shelter API with a front door

The Happy Tails animal shelter needs an API. Anyone should be able to browse the animals. Only shelter staff, holding a token, should be able to add or change one. And only the manager, with a username and password, should see the numbers. Tonight you build all of that in one Next.js app, one step at a time, testing each step in Postman before you move on.

This lab is meant to stretch you. Every step tells you what to build and how to check it. If you get stuck, every step also links to the full code for that step in the Code reference at the back. Try it yourself first, then look.

2Public: one pet

Make app/api/pets/[id]/route.ts. The square brackets mean "any value goes here," so this one file answers /api/pets/1, /api/pets/2, and so on. Next hands your function that value as its second input:

export async function GET(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  // id is text: "2", not 2
}

Find the pet whose id matches. Watch out: id from the address is text, and the ids in the array are numbers, so "2" === 2 is false. Turn it into a number with Number(id) first.

If there's no such pet, find gives you undefined. Don't let that slide through. Answer 404 yourself, with an error body in the same shape every time:

return Response.json({ error: `No pet with id ${id}` }, { status: 404 });

This file is one folder deeper, so the import goes up four folders.

3POST: add a pet

Go back to app/api/pets/route.ts and add a second function, POST, next to GET. Same address, different verb, different function.

Read the body with await request.json(). It throws if the body isn't JSON, so wrap it in try/catch and answer 400:

let body;
try {
  body = await request.json();
} catch {
  return Response.json({ error: "The body must be JSON" }, { status: 400 });
}

Then check every field before you save anything. Each failed check is a 400 with its own message:

  • name must be a string and not empty. Use typeof body.name !== "string".
  • species must be one of allowedSpecies. Import it too, and use allowedSpecies.includes(body.species).
  • age must be a number, 0 or more.

Only when all three pass do you build the new pet: id is pets.length + 1, adopted starts as false. Push it onto pets and return it with status 201 ("created"). Response.json always says 200 unless you tell it otherwise.

4PUT: replace a pet

Add a PUT function to app/api/pets/[id]/route.ts, next to its GET. It takes the same two inputs as GET (the request and the params).

PUT vs. PATCH

PUT means "here is the whole new pet, replace the old one." The client must send every field. PATCH (what lecture did) means "change only the fields I sent." Tonight is PUT, so a body missing any field is a 400.

In order, the function should:

  1. Find the pet, exactly like GET does. Not found: 404.
  2. Read the body in a try/catch, exactly like POST. Not JSON: 400.
  3. Run the same three checks as POST, plus a fourth: adopted must be true or false (typeof body.adopted !== "boolean").
  4. Change the pet you found (pet.name = body.name, and the same for the other three) and return it with 200. Leave its id alone.

Copying the checks from POST is fine. Recognizing a pattern you already wrote is the point.

5Private: a token in .env.local

Staff will prove who they are with a token: a secret string sent with every request. The token is a secret, so it never goes in your code. It goes in an environment file.

5a. Make sure Git will ignore it

Open .gitignore at the top of the repo and find the .env* line. That's what keeps env files out of Git. Every project you make from now on needs that line before you create the file.

5b. Make .env.local

Make a file called .env.local in week11/lab1/, right next to package.json (not inside app/):

API_TOKEN=shelter-staff-2026

No quotes, no spaces around the =. Next picks it up without a restart. The terminal prints Reload env: .env.local. Your code reads it as process.env.API_TOKEN. Never give it a NEXT_PUBLIC_ prefix. That prefix means "paste this into the browser's code," which is exactly where a secret must not go.

5c. How the token is sent

Lecture used a made-up header called x-auth. The standard place for a token is the Authorization header, and the value is the word Bearer, a space, then the token. "Bearer" means "whoever bears (carries) this token gets in."

Authorization: Bearer shelter-staff-2026

5d. Check it in POST

At the very top of your POST function, before reading the body, compare the header to what it should be. If it doesn't match, answer 401 ("I don't know who you are") and stop:

if (request.headers.get("authorization") !== `Bearer ${process.env.API_TOKEN}`) {
  return Response.json({ error: "Missing or wrong token" }, { status: 401 });
}

Test in Postman

To send the token: Authorization tab, Auth Type = Bearer Token, paste shelter-staff-2026 into Token. Then look at the Headers tab and show the hidden headers. There's the Authorization: Bearer ... line Postman built for you.

6proxy.ts: one file before every route

proxy.ts is a single file whose function runs before every request reaches any route. Start it the way lecture did, as a logger only, so you can prove it's running before you trust it with anything.

Make proxy.ts in the top folder of the project, next to package.json, not inside app/:

week11/lab1/
  app/
  types/
  .env.local
  package.json
  proxy.ts      <-- here
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

export function proxy(request: NextRequest) {
  console.log("proxy saw:", request.method, request.nextUrl.pathname);
  return NextResponse.next();
}

NextResponse.next() means "carry on to the route." Right now the proxy lets everything through. It only watches.

7Move the token check into the proxy

Now give the proxy a job. Copy your token check from POST into the proxy, between the log line and return NextResponse.next(). In the proxy the header comes from the same place: request.headers.get("authorization").

Then delete the check from POST. One place decides who gets in. If the check lives in two places, one day they'll disagree.

The rule from lecture: what the proxy returns decides what happens next. NextResponse.next() means carry on to the route. A Response.json(..., {status: 401}) means stop here, and the route never runs.

8Let the public routes back in

Give the proxy a list of the routes anyone may use, and check that list first. Public means reading only. GET /api/pets is public, but POST /api/pets is the same address with a different verb, and it must stay locked. So the check needs both the verb and the address.

At the top of proxy.ts, above the proxy function:

// Anyone may READ these without a token. Writing to them still needs one.
const publicPaths = ["/api/health", "/api/pets"];

function isPublic(method: string, path: string) {
  if (method !== "GET") return false;
  return publicPaths.includes(path) || path.startsWith("/api/pets/");
}

Why the extra startsWith? /api/pets/2, /api/pets/3 and so on can't all be typed into a list, so everything under /api/pets/ counts too.

Then, inside proxy, before the token check: if isPublic(request.method, request.nextUrl.pathname) is true, return NextResponse.next() straight away.

The teaching point: deny by default

You listed what's open and locked everything else. The other way round (list what's locked, leave everything else open) feels the same today. But the day someone adds /api/pets/delete-all and forgets to add it to the "locked" list, it's open to the world. With your way, a new route you forget about is locked until someone decides otherwise. When you forget, it stays safe.

9Logging that helps

proxy saw: GET /api/pets proved the proxy was running. It isn't enough once the proxy is making decisions. When someone says "I got a 401 at about 2:15," you want to find that line and see why. Good log lines follow a few rules:

  1. One line per request, the same shape every time, so your eye (or a search) can scan down them.
  2. When, what verb, what address at the start of every line. new Date().toISOString() gives you a timestamp like 2026-10-08T18:59:52.845Z.
  3. Say what was decided and why: -> public, -> allowed (token), -> 401 missing or wrong token.
  4. console.warn for things that went wrong (a 401, a bad body), console.log for normal traffic. Later, real log tools can filter on that.
  5. Log when the data changes: created pet 7 (Nugget), updated pet 3 (Pepper). Don't bother logging every read. The proxy already has those.
  6. Never log a secret. Not the token, not a password, not the whole Authorization header.

That last rule is the one that gets people fired. Logs get pasted into chat, screenshotted for help, and shipped off to logging services that lots of people can read. A line like this hands your key to every one of them:

console.log("auth header:", request.headers.get("authorization"));   // NEVER

Log what kind of check happened and what was decided, never the value that was checked.

9a. In the proxy

Build the start of the line once, at the top of proxy, and use it on every path out of the function:

const path = request.nextUrl.pathname;
const line = `${new Date().toISOString()} ${request.method} ${path}`;

// ...then before each return:
console.log(line, "-> public");
console.warn(line, "-> 401 missing or wrong token");
console.log(line, "-> allowed (token)");

Delete the old proxy saw: line.

9b. In the routes

In POST, right after the push: console.log(`created pet ${pet.id} (${pet.name})`). In PUT, after the changes: updated pet .... Before each 400, a console.warn that says which check failed, like console.warn("POST /api/pets: bad species", body.species). The species someone typed isn't a secret, so it's fine to log, and it's exactly what you'd want to know.

10Errors that help

Every error your API sends should tell the caller two things: whose fault it was (the status code) and what to do about it (the message). You already do that for the problems you thought of. This step is about the ones you didn't.

10a. Break it

Send a POST /api/pets with your Bearer token, Body set to raw JSON, and this as the whole body:

null

null is perfectly valid JSON, so request.json() doesn't throw, and your try/catch from Step 3 lets it through. Then body.name asks for a property of nothing, and the whole function crashes.

What you should see

Postman: 500 with an empty body. Whoever called your API now knows only "something broke," not what or why. The terminal knows exactly (your line numbers may differ):

⨯ TypeError: Cannot read properties of null (reading 'name')
    at POST (app\api\pets\route.ts:19:19)
> 19 |   if (typeof body.name !== "string" || body.name === "") {

Try the same on PUT /api/pets/2. Same crash.

10b. Two kinds of error

The client's faultOur fault
ExamplesBad JSON, a missing field, a wrong token, a pet that doesn't existA bug in our code, something we never expected
Status4xx: 400, 401, 404500
MessageExactly what's wrong and how to fix it: "age must be a number, 0 or more"Short and plain: "Something went wrong on our side"
Logconsole.warn, saying which check failedconsole.error with the whole error, so you can find the line

The null body is the client's mistake, but your API answered "500, our fault" and said nothing useful. Two fixes, in this order.

10c. Fix 1: a safety net

Wrap everything inside POST in one more try/catch. The inner one you already have still catches the failure you planned for (a body that isn't JSON). The new outer one catches every failure you didn't:

export async function POST(request: Request) {
  try {
    let body;
    try {
      body = await request.json();
    } catch {
      return Response.json({ error: "The body must be JSON" }, { status: 400 });
    }

    // ...all your checks, the push and the 201, unchanged...
  } catch (error) {
    console.error("POST /api/pets crashed:", error);
    return Response.json({ error: "Something went wrong on our side" }, { status: 500 });
  }
}

Send null again. Now Postman gets a 500 with {"error": "Something went wrong on our side"}, the same shape as every other error. The terminal has your line with the full details:

POST /api/pets crashed: TypeError: Cannot read properties of null (reading 'name')
    at POST (app\api\pets\route.ts:22:21)

The details go in the log, never in the response

It's tempting to send error.message back so the caller "knows what happened." Don't. Error messages and stack traces show your file names, your code, and sometimes data that's none of the caller's business. The caller gets a plain sentence. You get the details, in your own terminal. Same rule as Step 9: the log is for you.

10d. Fix 2: turn the 500 into a 400

Read that log line. It says body was null. That's not a bug in your code, it's bad input, and bad input is a 400 that tells the caller what to send. Add a check right after reading the body, before the name check:

// null is valid JSON, but body.name would crash on it.
if (body === null || typeof body !== "object") {
  return Response.json(
    { error: "The body must be a JSON object with name, species and age" },
    { status: 400 }
  );
}

That's the habit: whenever the safety net catches something that was really the client's mistake, add a check so it never gets that far again. The safety net stays for whatever you haven't thought of yet.

Now do both fixes in PUT. Its message should list all four fields: "The body must be a JSON object with name, species, age and adopted".

The GET routes don't need any of this. Nothing a caller sends can make find() or Response.json(pets) throw. Put try/catch where things can really fail: reading a body, decoding something (Step 11), and next week, talking to a database.

11The manager's door: Basic auth

The manager wants a summary, but a staff token shouldn't be enough to see it. Managers log in with a username and password. The oldest, simplest way to send those over HTTP is Basic auth, and you're going to check it by hand.

11a. The summary route

  • total: how many pets
  • adopted: how many have adopted: true. Use pets.filter(...), then .length.
  • waiting: total minus adopted

Restart the server first (Ctrl+C, npm run dev) so the list is fresh and your numbers match these. Then test it with your Bearer token: 200, {"total":6,"adopted":1,"waiting":5}. Without a token: 401. Right now it's just another locked route.

11c. What Basic auth actually sends

The client glues the username and password together with a colon, then base64-encodes the result, and sends that after the word Basic:

admin:adopt-dont-shop                       glued together with a colon
YWRtaW46YWRvcHQtZG9udC1zaG9w                base64-encoded
Authorization: Basic YWRtaW46YWRvcHQtZG9udC1zaG9w

Try it yourself. Open any browser tab's DevTools console and type btoa("admin:adopt-dont-shop"), then atob("YWRtaW46YWRvcHQtZG9udC1zaG9w"). btoa encodes and atob decodes, and both exist in the browser and on your Next server.

Base64 is not encryption

You just decoded a password with one function and no key. Base64 only turns any text into safe, plain letters for a header. Anyone who sees the header has the password. That's why Basic auth is only ever OK over HTTPS, where the whole request is encrypted on the way. localhost is fine for learning.

11d. Check it in the proxy

The server does the client's steps backwards. Add a new block to proxy for any address that starts with /api/admin. Put it after the public check and before the token check. (Think about why the order matters: what would the token check do to a request carrying Basic ...?)

  1. Accept the header: const auth = request.headers.get("authorization") ?? "";. The ?? "" turns "no header" into an empty string, so the next line can't crash.
  2. If it doesn't start with "Basic ", answer 401.
  3. Base64-decode the part after "Basic ": atob(auth.slice("Basic ".length)) gives you "admin:adopt-dont-shop". But atob throws if that text isn't real base64, so this is a Step 10 moment: wrap it in try/catch. Junk in the header is the client's mistake, so the catch answers 401 with a message that says what was expected, not a 500. (See the snippet below.)
  4. Split on the colon: const [user, pass] = decoded.split(":");
  5. Compare both to process.env.ADMIN_USER and process.env.ADMIN_PASS. Either one wrong: 401.
  6. Both right: log it and return NextResponse.next().

The decode, with its try/catch. decoded is declared outside the try so the lines after it can use it:

let decoded;
try {
  decoded = atob(auth.slice("Basic ".length));
} catch {
  return Response.json(
    { error: "Basic auth must be base64 of username:password" },
    { status: 401, headers: askForLogin }
  );
}

const [user, pass] = decoded.split(":");

Every admin 401 sends one extra header, which tells a browser to pop up its login box. Make it once at the top of the admin block and reuse it on every 401:

const askForLogin = { "WWW-Authenticate": 'Basic realm="admin"' };

return Response.json(
  { error: "Wrong username or password" },
  { status: 401, headers: askForLogin }
);

Log the decision like every other path (-> 401 wrong admin login (user "admin"), -> allowed (admin "admin")). The username is OK to log. The password never is.

Things that will bite you

  • Postman on the web can't reach localhost. Use the desktop app.
  • Saving a file can reset the list. While npm run dev runs, saving reloads the code, and the array goes back to what types/pet.ts says. That isn't your POST being broken. Re-run it.
  • proxy.ts in the wrong folder does nothing, silently. Top folder, next to package.json.
  • .env.local in the wrong folder means process.env.API_TOKEN is undefined, and every token is wrong. Same folder as package.json. The terminal lists Environments: .env.local at startup when it's found.
  • A 500 with an empty body means something threw. Postman won't tell you what. The terminal will, down to the line. Read it before you change anything.
  • Body type set to Text instead of JSON in Postman makes every POST a 400 "The body must be JSON".
  • "age": "2" is text. "age": 2 is a number. Same for "adopted": "true" vs "adopted": true.
  • The Authorization tab and a hand-typed Authorization header fight. If you type the header yourself on the Headers tab, set the Authorization tab to No Auth.
  • A browser visit logs extra requests like GET /favicon.ico -> 401. That's the browser asking for a tab icon, and your proxy correctly locking an address that isn't on the public list. Harmless.
  • Claude says middleware.ts. That's the Next 15 name. In Next 16 it's proxy.ts with a function called proxy.
  • Port 3000 taken? Next picks 3001 and says so in the terminal. Use whatever it says, or stop the other npm run dev.

import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

// Anyone may READ these without a token. Writing to them still needs one.
const publicPaths = ["/api/health", "/api/pets"];

function isPublic(method: string, path: string) {
  if (method !== "GET") return false;
  return publicPaths.includes(path) || path.startsWith("/api/pets/");
}

export function proxy(request: NextRequest) {
  const path = request.nextUrl.pathname;
  // Same start to every line: when, what verb, what address. Never the token.
  const line = `${new Date().toISOString()} ${request.method} ${path}`;

  if (isPublic(request.method, path)) {
    console.log(line, "-> public");
    return NextResponse.next();
  }

  const auth = request.headers.get("authorization") ?? "";

  if (auth !== `Bearer ${process.env.API_TOKEN}`) {
    console.warn(line, "-> 401 missing or wrong token");
    return Response.json({ error: "Missing or wrong token" }, { status: 401 });
  }

  console.log(line, "-> allowed (token)");
  return NextResponse.next();
}

import { pets, allowedSpecies } from "../../../types/pet";

}

export async function POST(request: Request) {
  // The outer try is the safety net: anything we didn't plan for becomes a clean 500.
  try {
    // The inner try catches the one failure we did plan for: a body that isn't JSON.

    if (body === null || typeof body !== "object") {
      console.warn("POST /api/pets: body was not an object", body);
      return Response.json(
        { error: "The body must be a JSON object with name, species and age" },
        { status: 400 }
      );
    }
    if (typeof body.name !== "string" || body.name === "") {
      console.warn("POST /api/pets: no name");
      return Response.json({ error: "name is required" }, { status: 400 });
    }
    if (!allowedSpecies.includes(body.species)) {
      console.warn("POST /api/pets: bad species", body.species);
      return Response.json({ error: "species must be dog, cat or rabbit" }, { status: 400 });
    }
    if (typeof body.age !== "number" || body.age < 0) {
      console.warn("POST /api/pets: bad age", body.age);
      return Response.json({ error: "age must be a number, 0 or more" }, { status: 400 });
    }

    const pet: Pet = {
      id: pets.length + 1,
      name: body.name,
      species: body.species,
      age: body.age,
      adopted: false,
    };
    pets.push(pet);
    console.log(`created pet ${pet.id} (${pet.name})`);

    console.error("POST /api/pets crashed:", error);

    pet.name = body.name;
    pet.species = body.species;
    pet.age = body.age;
    pet.adopted = body.adopted;
    console.log(`updated pet ${pet.id} (${pet.name})`);
    return Response.json(pet);
  } catch (error) {
    // Our fault, not the client's. The details go in OUR log, never in the response.
    console.error(`PUT /api/pets/${id} crashed:`, error);
    return Response.json({ error: "Something went wrong on our side" }, { status: 500 });
  }
}

// Goes in the top folder, next to package.json. Anywhere else, Next never calls it.
// Every request passes through here before it reaches a route.
// Needs .env.local with API_TOKEN, ADMIN_USER and ADMIN_PASS.
import { NextResponse } from "next/server";
import type { NextRequest } from "next/server";

// Anyone may READ these without a token. Writing to them still needs one.
const publicPaths = ["/api/health", "/api/pets"];

function isPublic(method: string, path: string) {
  if (method !== "GET") return false;
  return publicPaths.includes(path) || path.startsWith("/api/pets/");
}

export function proxy(request: NextRequest) {
  const path = request.nextUrl.pathname;
  // Same start to every line: when, what verb, what address. Never the token or password.
  const line = `${new Date().toISOString()} ${request.method} ${path}`;

  // 1. Public routes: let them straight through.
  if (isPublic(request.method, path)) {
    console.log(line, "-> public");
    return NextResponse.next();
  }

  const auth = request.headers.get("authorization") ?? "";

  // 2. Admin routes: a username and password (Basic auth).
  if (path.startsWith("/api/admin")) {
    // The WWW-Authenticate header makes a browser pop up its login box.
    const askForLogin = { "WWW-Authenticate": 'Basic realm="admin"' };

    if (!auth.startsWith("Basic ")) {
      console.warn(line, "-> 401 no admin login sent");
      return Response.json(
        { error: "Admin login required" },
        { status: 401, headers: askForLogin }
      );
    }

    // atob throws if the text isn't real base64.
    // That's the client's mistake, so it's a 401, not a 500.
    let decoded;
    try {
      decoded = atob(auth.slice("Basic ".length)); // "YWRtaW46..." -> "admin:password"
    } catch {
      console.warn(line, "-> 401 admin login was not base64");
      return Response.json(
        { error: "Basic auth must be base64 of username:password" },
        { status: 401, headers: askForLogin }
      );
    }

    const [user, pass] = decoded.split(":");

    if (user !== process.env.ADMIN_USER || pass !== process.env.ADMIN_PASS) {
      console.warn(line, `-> 401 wrong admin login (user "${user}")`);
      return Response.json(
        { error: "Wrong username or password" },
        { status: 401, headers: askForLogin }
      );
    }

    console.log(line, `-> allowed (admin "${user}")`);
    return NextResponse.next();
  }

  // 3. Everything else: the staff token (Bearer).
  if (auth !== `Bearer ${process.env.API_TOKEN}`) {
    console.warn(line, "-> 401 missing or wrong token");
    return Response.json({ error: "Missing or wrong token" }, { status: 401 });
  }

  console.log(line, "-> allowed (token)");
  return NextResponse.next();
}
