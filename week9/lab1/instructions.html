Finish the Tailwind pass, then play with flex and positioning

The Daily Grind, mid-conversion. The header, the menu grid, and the product cards already got the Tailwind treatment in class. Every button and the whole cart section are still the old globals.css classes. Tonight you finish the job, then use flex and position for two things Tailwind's utility classes are especially good at: laying boxes out next to each other, and pinning one small thing on top of another.

1. Run it, and spot the seam

npm install
npm run dev

Open http://localhost:3000. Look closely at the page: the header is a row, the cards have a border and a hover, the menu is a responsive grid. Then look at every button (Order now, Add to cart, Checkout, Place order) and the cart box at the bottom — different font, a plain grey border, no hover. That's the seam between what got converted in class and what didn't.

Open app/globals.css. Everything below the comment /* Everything below here is not yet converted — today's job. */ is a plain CSS class with a matching className somewhere in components/ or app/. Same two-file problem as week 3.

2. Convert every button

Required. Four places use className="add-btn": components/Header.tsx, components/ProductCard.tsx, app/cart/page.tsx, and app/checkout/page.tsx. Replace add-btn on all four with utility classes:

className="bg-amber-900 text-white px-4 py-2 rounded hover:bg-amber-800"

One more: components/CartItem.tsx has a remove-btn. It was never meant to look like the other buttons — it's plain text with a colour, no background. Give it: 

className="text-red-600 hover:underline"

Stop and check. Every button on the page should now look the same (dark brown, white text) except Remove, which should look like a plain red link. If a button still looks unstyled, the class name is probably still add-btn or remove-btn somewhere.

3. Convert the cart box

Required. In components/CartList.tsx and components/CartItem.tsx, replace the remaining classes one at a time:

Old classReplace with
cartborder border-gray-300 rounded-lg p-4 mt-8
cart-emptytext-gray-500
cart-listlist-none p-0 m-0
cart-totalfont-bold border-t border-gray-300 mt-3 pt-3

Leave cart-item alone for a moment — that one's next, and it's the interesting one.

4. Flex a row of things that aren't a header

Required. Add an item or two to the cart (click Add to cart on the menu) and look at a cart line: the name, the quantity, the price, and Remove are all stacked with no relationship to each other. In class, flex on the <header> turned four stacked things into a row with space between them. Same move, different element. On the <li className="cart-item"> in components/CartItem.tsx:

className="flex items-center justify-between gap-2 py-1"

Name and quantity settle to the left, Remove to the right, everything lined up on one axis. That's the same three utilities from the header — flex, items-center, justify-between — doing the identical job at a completely different scale.

5. Delete the CSS you just replaced

Required. Once every button and the whole cart section look right, delete the rules you replaced from app/globals.css: add-btn, cart, cart-empty, cart-list, cart-item, remove-btn, cart-total. Reload. Nothing should change on screen — if something does, a className somewhere is still pointing at a rule you just deleted.

AI hint — before the next section. If you're not sure why deleting unused CSS is worth doing instead of just leaving it there, ask:

"In a codebase using Tailwind, what goes wrong over time if old, unused CSS classes are left in the stylesheet instead of deleted once a component stops using them?"

6. Put the menu and the cart side by side

Required. Right now app/page.tsx just stacks <MenuList /> on top of <CartList /> inside a plain <main>. On a wide screen there's room for both at once. Wrap them in a flex row that only kicks in from md up — phone first, same rule as class:

<main className="flex flex-col md:flex-row gap-8 items-start">
  <div className="md:flex-1">
    <MenuList onAdd={handleAdd} />
  </div>
  <div className="md:w-80 md:sticky md:top-4">
    <CartList cart={cart} onRemove={handleRemove} />
  </div>
</main>

md:flex-1 lets the menu column take up whatever space is left. md:w-80 gives the cart a fixed width instead of stretching. md:sticky md:top-4 is the new one: it pins the cart 4 units from the top of the viewport once you scroll far enough that it would otherwise scroll out of view — but only within its own parent, and only from md up. Resize the window below 768px and watch the cart drop back under the menu and stop being sticky; a sticky element with nothing above it to scroll past just sits where it is.

Expect this one. sticky does nothing if the element's parent is exactly as tall as the element itself — there has to be something to scroll past. If it doesn't seem to stick, add a couple more drinks to types/coffee.ts so the menu column is taller than the cart, or shrink the browser window's height.

7. Pin a badge to a card

Required. types/coffee.ts already marks the seasonal drink with isNew: true. In components/ProductCard.tsx, show a small "New" badge in the corner of that one card. Two moves, and they always come as a pair:

  1. Add relative to the <article>'s className — it doesn't move anything, it just tells the browser "this box is the one any absolutely positioned thing inside it should measure itself against."
  2. Render the badge only when drink.isNew, positioned against that box:
{drink.isNew && (
  <span className="absolute top-2 right-2 bg-amber-900 text-white text-xs px-2 py-1 rounded">
    New
  </span>
)}

The seasonal drink's name is long enough to run under the badge. Give the <h2> some breathing room on that side: text-xl pr-14.

Stop and check. The badge should sit in the top-right corner of that card, not the top-right corner of the page, and the drink name shouldn't run underneath it. Remove relative from the article as a test — the badge jumps to the corner of the nearest ancestor that does have it (or the page, if nothing does). Put relative back before moving on.

8. If there's time: more variations

Tailwind is mostly muscle memory at this point — pick a few and see what happens:

  • Add shadow-md hover:shadow-lg transition-shadow to the product cards, on top of the existing border and hover background.
  • Round the corners of the cards and the cart box further with rounded-xl, or drop them to rounded-none and see how much of the "card" feeling that border alone was carrying.
  • Make the header itself sticky: sticky top-0 bg-white z-10 (it needs a background, or the menu will show through it while scrolling).
  • Give the "New" badge a second colour variant for an "Out of stock" state on a different drink, using the same relative/absolute pair.

AI hint — going deeper. Once the sticky cart and the badge both work, ask:

"What CSS property besides `position: sticky` and `position: absolute` also takes an element out of the normal document flow, and why does that matter for layout?"

That's a bigger question than tonight's lab needs, but it's the next thing worth knowing.

What "done" looks like

  • No button on the page still says add-btn or remove-btn in the source, and app/globals.css no longer has rules for classes nothing uses.
  • A cart line lays its four pieces out in a row with Remove pushed to the right.
  • On a wide window, the menu and the cart sit side by side and the cart stays in view while the menu scrolls. On a narrow window, they stack.
  • The seasonal drink's card shows a "New" badge pinned to its own top-right corner.
