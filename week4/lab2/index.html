What to make this page do

Right now all three cards are on the screen at once, and the Next and Back buttons do nothing. That's on purpose. Your job is to turn this long form into one card at a time.

The HTML and CSS are finished. script.js is already connected at the bottom of this page, and it is empty.

First, prove the connection. Put console.log('connected'); in script.js, reload this page, and open the console (right-click → Inspect → Console). If you don't see the word connected, stop and fix that before writing anything else.

You already have the tool for this. The stylesheet contains a class called hidden that does nothing except make something disappear. Adding and removing that one class from a card is the whole trick: document.getElementById('step-2').classList.add('hidden');

Action 1 — Required

When the page loads, only Step 1 is showing. Cards 2 and 3 are hidden.

Action 2 — Required

Clicking Next on step 1 hides step 1 and shows step 2. Clicking Next on step 2 hides step 2 and shows step 3. That's the whole wizard — two clicks, four lines.

Action 3 — Required

The Back buttons do the reverse. Somebody who clicks Next by mistake has to be able to get out of it, and a wizard with no way back is a trap.

Action 4 — Optional

Clicking Place order shows a message in the empty box at the bottom that repeats back what they picked — the coffee, the grind, and the name they typed.

Action 5 — Optional

Don't let them place an order with nothing in step 3. If the name or the email is empty when they click Place order, don't show the confirmation — mark the empty boxes instead, by putting the class is-invalid on them: 

document.getElementById('name').classList.add('is-invalid');

The box turns red and a short red line of text appears under it. That text is already written and already in the HTML; it stays hidden until the box next to it is marked, so you get the message for free. Only mark the ones that are actually empty.

And take the class off again when they fix it. This is the half everybody forgets. Somebody leaves the email blank, gets a red box, types their email, clicks again — and the box is still red, because nothing ever removed the class: 

document.getElementById('email').classList.remove('is-invalid');

Every box should end up marked or unmarked based on what's in it right now, not on what was wrong last time. This bug is in real, shipped, paid-for software everywhere. Now you'll see it for the rest of your life.

Action 6 — Optional, and it will fight you

Make the three dots at the top keep up. The current step's dot has the class on; the others don't. Move it as they move.

Class that marks a box as wrongis-invalid

Where is-invalid comes from. It isn't a name we made up. It's Bootstrap's — the styling library you met in Week 3 as "somebody else's stylesheet" — and it is what Bootstrap forms use to mark a bad field everywhere in the world. This page doesn't load Bootstrap; the red box and the red text are written into styles.css by hand, using Bootstrap's name and Bootstrap's exact red, so that what you learn here is what you'd type on a real Bootstrap form later. The partner class on the little red message is invalid-feedback, also Bootstrap's.

Expect this one. The console says null, or "cannot read properties of null". That means you asked the page for something that isn't there under that name. Check the id in the HTML against the one in your JavaScript, one character at a time — it is almost always a capital letter or a missing dash. Write it in your log before you fix it.
