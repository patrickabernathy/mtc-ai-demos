From one HTML page to components

You have a finished library page written in plain HTML and CSS. Tonight you build that same page in Next.js, then cut it into four components — one of which takes typed props. Nothing on this page can be clicked. It is all layout.

1. Make the Next.js app

Open a terminal in this lab folder (the one holding index.html) and run: 

npx create-next-app@latest library-app

It asks a pile of questions. Answer them exactly like this — these are the settings we use for every project in this class:

It asksYou answer
What is your project named?library-app
Would you like to use the recommended defaults?Customize — don't take the defaults
Would you like to use TypeScript?Yes
Which linter would you like to use?None
Would you like to enable React Compiler?No
Would you like to use Tailwind CSS?Yes
Would you like your code inside a src/ directory?Yes
Would you like to use App Router?Yes
Would you like to customize the import alias?No
Would you like to create an AGENTS.md file?No

The exact wording and the order of these move around between versions of Next. Answer what's on your screen, not what's in the second column of a table — if you get a question that isn't listed here, take the recommended answer and write the question down so we can talk about it.

Then start it:

cd library-app
npm run dev

Open http://localhost:3000. You should get the Next.js starter page. Leave npm run dev running the whole night — it rebuilds every time you save.

Know where you are. Because you said yes to src/, your code lives in src/app/, not app/. Every path in these instructions starts from inside library-app.

2. Move the stylesheet over

You said yes to Tailwind, so src/app/globals.css already has Tailwind's own setup in it plus a few starter rules. We're not writing Tailwind classes tonight — we're bringing our own CSS, the same CSS you already have.

  1. Open src/app/globals.css.
  2. Keep the very first line, @import "tailwindcss";.
  3. Delete everything else in that file.
  4. Paste the entire contents of this lab's styles.css underneath it.

Nothing changes on screen yet, because page.tsx is still the Next starter. That's fine.

Expect this one. Tailwind quietly resets a lot of browser defaults — heading sizes, list bullets, paragraph margins. Our stylesheet sets all of that back on purpose, so the page should look right. But if something is mysteriously the wrong size and it isn't in styles.css, that's who did it. Inspect the element and look at what's crossed out.

While you're in there

Open src/app/layout.tsx and change the title and description in metadata to match this page. That export is the <title> tag — there is no <head> for you to edit, because there is no index.html any more. The <html> and <body> tags moved here, written once for the whole site.

3. Rebuild the page in JSX

Open index.html in a browser and look at it. That is the finished thing. Your job is to make the same page come out of Next instead of out of a .html file.

Open src/app/page.tsx, delete everything in it, and start over: 

export default function Home() {
  return (
    <div>
      {/* the page goes here */}
    </div>
  );
}

Then copy the markup from index.html — everything between <body> and </body>, not the <head> — into that <div> and fix it until it compiles. It will not compile on the first try. JSX looks like HTML and is not HTML.

The five things that will break

In HTMLIn JSXWhy
class="card" className="card" class is a reserved word in JavaScript.
<br>, <img src="..."> <br />, <img src="..." /> Every tag has to close. No exceptions.
<!-- note --> {/* note */} HTML comments aren't valid inside JSX.
for="name" htmlFor="name" Same reason as class. No labels on this page, but you'll hit it soon.
Two tags side by side Wrap them in one parent A component returns one thing. Use a <div>, or <>...</>.

Expect this one. The nav has three links separated by &middot;. When you break those onto separate lines, JSX eats the spaces around them and you get Catalog·Events·Ask jammed together. The fix is {" "} — a literal space, written as JavaScript: 

<a href="#">Catalog</a> &middot;{" "}
<a href="#">Events</a> &middot;{" "}
<a href="#">Ask a librarian</a>

Write this one in your log. Everyone hits it, nobody guesses it.

Stop here and check. Before you split anything into components, the page at localhost:3000 should look identical to index.html — same colors, same three cards, same footer. Put the two windows side by side. If they don't match, fix it now. Refactoring a page that's already wrong just gives you two problems.

4. Break it into components

Right now page.tsx is one long wall of JSX. That is exactly what a real page looks like right before somebody cleans it up, and cleaning it up is the point of tonight.

Make a folder src/components/ and build these four. One file each.

ComponentWhat goes in itProps
Header.tsxThe whole <header> blocknone
Nav.tsxThe whole <nav> blocknone
InfoCard.tsxOne <li class="card">three — see below
Footer.tsxThe whole <footer> blocknone

Start with Header, because it is the easy one:

// src/components/Header.tsx

export function Header() {
  return (
    <header>
      {/* ...the header markup, moved out of page.tsx... */}
    </header>
  );
}

And at the top of page.tsx:

import { Header } from "@/components/Header";

That @/ means "start at src/". It is the import alias you said yes to during setup, and it saves you from counting ../../ for the rest of your life.

Check. After Header is pulled out, the page should look exactly the same. Nothing moved on screen. Only where the markup lives changed. If the page changed, you moved the wrong lines.

5. The one with props — InfoCard

The three cards are the same shape with different words in them. That is what a prop is for: one component, told what to say.

Required. InfoCard takes three props:

PropTypeWhat it is
titlestringThe <h3> — "Hours"
bodystringThe paragraph under it
detailstringThe small grey line at the bottom

Required. Write the type out on its own, above the component. Don't cram it inline. You want to be able to read it: 

// src/components/InfoCard.tsx

type InfoCardProps = {
  title: string;
  body: string;
  detail: string;
};

export function InfoCard({ title, body, detail }: InfoCardProps) {
  return (
    <li className="card">
      <h3>{title}</h3>
      {/* ...you finish it... */}
    </li>
  );
}

Those curly braces in { title, body, detail } are destructuring — the same thing you did to plain objects in JavaScript. React hands your component one object with all the props in it; this pulls the three you want out of it by name.

Then use it three times in page.tsx:

<ul className="cards">
  <InfoCard
    title="Hours"
    body="Open 9 to 7 Monday through Thursday, 9 to 5 on Friday and Saturday, closed Sunday."
    detail="The book drop out front is unlocked all night."
  />
  {/* ...two more... */}
</ul>

Prove the types are real. This is the part people skip, and it is the only part that shows you what TypeScript is for.

  1. Delete detail="..." from one of the three cards. Save.
  2. Your editor should underline <InfoCard> in red before you run anything at all.
  3. Run npm run build in a second terminal. It should fail, and the error should name the missing prop.
  4. Now try title={42}. Read that error too. Then put everything back.

Nothing was running. Nobody clicked anything. The mistake got caught while you were still typing. That is the whole pitch.

6. Optional, if you finish early

  • Add a fourth card — "Meeting rooms", or whatever you want. Notice you write six words instead of fifteen lines, because InfoCard already exists. That is the payoff.
  • Make detail optional: detail?: string. Then render the small grey line only when it was passed: {detail && <p className="detail">{detail}</p>}. Add a card with no detail and confirm the little divider line doesn't show up.
  • Move the three cards' text into an array of objects at the top of page.tsx and render them with .map(). React will warn you in the console about a missing key. That is lab 2 — look ahead if you want it.

What "done" looks like

  • The page at localhost:3000 is indistinguishable from index.html.
  • src/app/page.tsx is short — a header, a nav, three cards, a footer. The whole page fits on one screen.
  • There are four files in src/components/.
  • InfoCard has a named props type with three strings.
  • npm run build finishes with no errors.
