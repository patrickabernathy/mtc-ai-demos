1Install Drizzle and drizzle-kit

Stop the server (Ctrl+C) and install four packages, in two lines:

npm install drizzle-orm @neondatabase/serverless
npm install -D drizzle-kit dotenv
  • drizzle-orm is the part your app uses while it runs. You write db.select().from(items), and it turns that into SQL, sends it, and hands the rows back as JavaScript objects.
  • @neondatabase/serverless is the driver: how the SQL actually travels to Neon over the internet.
  • drizzle-kit is the half you run from the terminal. Tonight it does one job: read your database and write the TypeScript description of it for you.
  • dotenv lets drizzle-kit read .env.local. Next reads that file by itself; drizzle-kit is a separate program, so it doesn't.

-D means "only needed while building," so those two land under devDependencies in package.json.

Check it

Open package.json. drizzle-orm and @neondatabase/serverless are under dependencies; drizzle-kit and dotenv are under devDependencies.

2The connection string in .env.local

The connection string is the address and the password of your database in one line. It's a secret, so it goes in .env.local, which never gets committed. (Same rule as last week's token.)

  1. Open .gitignore in this folder and find the .env*.local line. That's what keeps the file out of Git.
  2. Make a new file called .env.local next to package.json. Make it in VS Code, not Notepad, so it doesn't secretly become .env.local.txt. Copy the one line from .env.example into it.
  3. In Neon, open your project and click Connect. Change the database dropdown to store before you copy. It starts on neondb, which is the wrong one.
  4. Paste the string after the =. No quotes, no spaces:
NEON_DATABASE_URL=postgresql://neondb_owner:****@ep-something.neon.tech/store?sslmode=require

Look at the end of yours: it should say /store?, not /neondb?.

Check it

Run git status. .env.local must not be listed. If it is, stop and ask: that string is a password, and this repo is public.

3drizzle.config.ts and a script

drizzle-kit needs to know four things, and a file called drizzle.config.ts tells it. Make it next to package.json:

import { defineConfig } from "drizzle-kit";
import dotenv from "dotenv";

dotenv.config({ path: ".env.local" });

export default defineConfig({
  dialect: "postgresql",             // which kind of database
  schema: "./drizzle/schema.ts",     // where our tables are described
  out: "./drizzle",                  // where drizzle-kit writes what it generates
  dbCredentials: { url: process.env.NEON_DATABASE_URL || "" },
});
  • dialect: which kind of database. Postgres.
  • schema: the file where your tables are described in TypeScript. It doesn't exist yet; the pull in Step 4 writes it.
  • out: the folder drizzle-kit writes into.
  • dbCredentials.url: how to reach the database. That only works because of the dotenv.config(...) line at the top, which loads .env.local into process.env first. The || "" just keeps TypeScript happy if it's missing.

Then add one line to the "scripts" in package.json, so the command has a name you can remember. Don't forget the comma at the end of the line above it:

"scripts": {
  "dev": "next dev",
  "build": "next build",
  "start": "next start",
  "db:pull": "drizzle-kit pull"
},

4b. Read it, then make one edit

Open drizzle/schema.ts, find export const items, and put db/0001_store.sql's CREATE TABLE items next to it. Every line matches. The name on the left is what your code calls the column (isAvailable); the one in quotes is its real name in Postgres (is_available).

Now the one edit. Postgres sends a numeric column back as text ("2.50"), because turning money into a JavaScript number can lose a fraction of a penny. The page calls coffee.price.toFixed(2), which only works on a number, so tell Drizzle to turn it into one. Change the price line in items:

price: numeric({ precision: 6, scale: 2, mode: "number" }).notNull(),

Every pull undoes this edit

Pulling again rewrites schema.ts from scratch, and mode: "number" is gone. Keep pulling anyway: when you add tables or run a new SQL file from db/, a pull is the easy way to get schema.ts to match the database again. Just redo your edits after every pull.

Hint: don't trust yourself to remember. Keep a short After every npm run db:pull list in your README, one line per edit. This lab's README.md has one; look at it.

5The Neon provider

A provider wraps one thing outside your app, here Neon, and is the only file that reads its secret and connects. Everything else asks the provider for the connection. If the connection ever changes, you change one file.

Make a folder providers, inside it a folder neon, and inside that neonDatabaseProvider.ts:

// The ONE file that knows how to reach the database.
// A provider wraps something outside our app: here, Neon.
import { neon } from "@neondatabase/serverless";
import { drizzle, type NeonHttpDatabase } from "drizzle-orm/neon-http";

export class NeonDatabaseProvider {
  // One copy for the whole app, made the first time somebody asks.
  private static instance: NeonDatabaseProvider;
  private db: NeonHttpDatabase | undefined;

  public static getInstance(): NeonDatabaseProvider {
    if (!NeonDatabaseProvider.instance) {
      NeonDatabaseProvider.instance = new NeonDatabaseProvider();
    }
    return NeonDatabaseProvider.instance;
  }

  public getDb(): NeonHttpDatabase {
    // ...you write this part
  }
}

The class, in three lines you copy

Wednesday's frame: instance is static, so there's one of it for the whole app. getInstance() makes it the first time anyone asks and hands back the same one every time after. So every route that says NeonDatabaseProvider.getInstance() gets the same provider, and the app connects once instead of once per request. You'll write the same three lines for the service in Step 6.

Now write getDb(). The first time it's called (this.db is still undefined):

  1. Read process.env.NEON_DATABASE_URL.
  2. If it's missing, throw new Error(...) with a sentence that says exactly what to do: "NEON_DATABASE_URL is not set. Copy .env.example to .env.local and fill it in." Failing loudly here, in plain words, beats a confusing crash somewhere else later.
  3. Otherwise connect: this.db = drizzle(neon(url));

Every time, at the end: return this.db;

Nothing to test yet

Nothing calls the provider until Step 6, so there's nothing to see. VS Code shouldn't show any red underlines in the file.

6The item service, and the list of coffees

The service is the one file that asks the database about items. Every query lives here, and so does every rule about the store. Routes call the service and never write a query themselves.

6a. The service

Make a folder services next to providers, and in it itemService.ts. Start with the imports, and the store's first rule: this screen is for coffees only, and coffee is category 1 in store.sql.

// The ONE file that knows how to ask the database about items.
// Routes call these methods. Routes never write a query themselves.
import { eq } from "drizzle-orm";
import { NeonDatabaseProvider } from "../providers/neon/neonDatabaseProvider";
import { items } from "../drizzle/schema";

// Coffee is category 1 in store.sql. This app only ever works on coffees,
// so every query below uses this rule, written once.
const coffeeCategoryId = 1;
const isCoffee = eq(items.categoryId, coffeeCategoryId);

eq(items.categoryId, 1) is Drizzle for the SQL category_id = 1. You're making it once, at the top, so every method below can use the same rule.

Then the class: the same three "one shared copy" lines as the provider (with ItemService instead of NeonDatabaseProvider), a small private helper that asks the provider for the connection, and your first query:

export class ItemService {
  // ...instance and getInstance(), like the provider

  private getDb() {
    return NeonDatabaseProvider.getInstance().getDb();
  }

  public async getCoffees() {
    return this.getDb().select().from(items).where(isCoffee).orderBy(items.id);
  }
}

Read that last line as SQL: SELECT * FROM items WHERE category_id = 1 ORDER BY id.

6b. The route calls it

In app/api/coffees/route.ts, import the service at the top. Count the folders: from app/api/coffees/ it's three ../ back to the project folder:

import { ItemService } from "../../../services/itemService";

Then replace the TODO (Step 6) line and the return Response.json([]); under it with two lines: ask the service, send what it gives you. Leave the Steps 11 and 12 TODO where it is.

const coffees = await ItemService.getInstance().getCoffees();
return Response.json(coffees);

Don't forget await

Talking to the database takes time, so getCoffees() gives back a Promise of rows, not the rows. Without await, Response.json gets the Promise, and a Promise turned into JSON is {}. The page then says "No coffees found." and nothing errors.

7One coffee

The edit page fills its form from GET /api/coffees/3. Two parts, the same as Step 6: a method on the service, then the route calls it.

7a. getCoffee(id) in the service

This query needs two rules at once: the id matches, and it's a coffee. Drizzle's and(...) joins them, like AND in SQL. Add and to the import from drizzle-orm:

import { and, eq } from "drizzle-orm";

Then add the method inside the class:

// Gives back undefined when there's no such coffee.
public async getCoffee(id: number) {
  const [coffee] = await this.getDb()
    .select()
    .from(items)
    .where(and(eq(items.id, id), isCoffee));
  return coffee;
}

A select always gives back a list, even when it can only find one row. const [coffee] = ... takes the first thing in the list. If the list is empty, coffee is undefined.

7b. The route

In app/api/coffees/[id]/route.ts, import the service. This file is one folder deeper, so it's four ../. In GET, replace the TODO and the 501: ask the service for Number(id) (the id in the address is text), answer 404 with {"error": "No coffee with id ..."} if it gave back nothing, otherwise send the coffee.

8Create: a new coffee

8a. The shape of a coffee coming in

Adding and changing a coffee both need the same four things from the route. Give that shape a name, at the top of the service under isCoffee, and export it:

// What a route hands over to add or change a coffee. The route checks it first.
export type CoffeeInput = {
  name: string;
  description: string | null;
  price: number;
  isAvailable: boolean;
};

8b. createCoffee(input)

// .returning() hands back the row Postgres saved, new id included.
// categoryId is added here, so a new coffee is always a coffee.
public async createCoffee(input: CoffeeInput) {
  const [coffee] = await this.getDb()
    .insert(items)
    .values({ ...input, categoryId: coffeeCategoryId })
    .returning();
  return coffee;
}

Two things worth noticing. You don't send an id: the table's serial column picks the next one. And without .returning() an insert gives back nothing, so you'd never learn the id Postgres chose. { ...input, categoryId: coffeeCategoryId } means "everything in input, plus categoryId." The route never chooses the category; the service does, using the same number as the rule.

8c. The route

In POST in app/api/coffees/route.ts, replace the TODO and the 501. Build the input from the body that was already checked, and answer 201 with the new coffee:

  • description: body.description || null. An empty box (or no description at all) becomes NULL, which is how store.sql says "nobody wrote one."
  • isAvailable: true. A new coffee starts on sale.

9Edit: change a coffee

The edit form sends the whole coffee back with PUT: every field, even the ones you didn't touch. (PUT means "here's the whole new thing, replace the old one," the same as week 11.) The route already checks all four fields.

9a. updateCoffee(id, input)

Write it yourself. It's getCoffee and createCoffee put together:

  • .update(items) instead of .insert(items)
  • .set(input): the new values for the columns
  • the same .where(...) as getCoffee, so only a coffee with that id changes
  • .returning(), and const [coffee] = ..., and return it. undefined means no coffee had that id.

The where is not optional

An update with no where changes every row in the table. Every item in the store would get the same name and price, and there's no undo. The isCoffee rule also means this route can't touch a sandwich, even if someone sends its id.

9b. The route

In PUT, replace the TODO and the 501. Call updateCoffee(Number(id), {...}) with the four fields (description: body.description || null again), answer 404 if it gave back nothing, otherwise send the changed coffee.

10Delete, and Tuesday's foreign key

10a. The obvious version

Add deleteCoffee(id) to the service. A delete has nothing worth giving back, so it doesn't need .returning():

public async deleteCoffee(id: number) {
  await this.getDb().delete(items).where(and(eq(items.id, id), isCoffee));
}

Same warning as Step 9, louder: a delete with no where empties the table.

In the route's DELETE, replace the TODO and the 501 with three moves: ask getCoffee first and answer 404 if there's no such coffee; then deleteCoffee; then answer 204 ("done, nothing to send back"). A 204 has no body at all:

return new Response(null, { status: 204 });

Since you call the service twice, keep it in a variable first: const service = ItemService.getInstance();.

10b. Whose fault is that 500?

Remember week 11's rule: 4xx is the client's fault, 500 is ours. This isn't a bug in your code, and the request wasn't bad either: "delete the Latte" is a perfectly sensible thing to ask. The data says no. HTTP has a status for exactly that: 409 Conflict, "your request is fine, but it conflicts with the state of things." And the owner deserves a sentence that says what to do instead.

The rule "a coffee that's been sold can't be deleted" is a rule about the store, so it belongs in the service. Add receiptItems to the schema import (import { items, receiptItems } from "../drizzle/schema";), then:

// Tuesday's foreign key: receipt_items points at items, so Postgres refuses
// to delete a coffee that's on an old receipt. Asking first lets the route
// say why, instead of crashing.
public async hasBeenSold(id: number) {
  const [line] = await this.getDb()
    .select()
    .from(receiptItems)
    .where(eq(receiptItems.itemId, id))
    .limit(1);
  return line !== undefined;
}

.limit(1) stops at the first receipt line it finds. You only need to know if there's one, not count all 26,000.

In the route, between the 404 check and the delete: if await service.hasBeenSold(coffee.id), answer 409 with {"error": "Latte is on old receipts, so it can't be deleted. Mark it sold out instead."} (use coffee.name, not the word Latte).

11Search by name: ?search=

Type lat in the search box and press Search. The page shows Asked: /api/coffees?search=lat, and you still get every coffee. The page sent the search; the route isn't listening yet.

11a. Watch the SQL first

This step is about what your code sends to Postgres, so make it visible. In the provider, change the connect line to turn on Drizzle's logger:

// logger: true prints every query and its params in the terminal (Step 11).
this.db = drizzle(neon(url), { logger: true });

Restart, refresh the list, and look at the terminal. Every query is now printed, with its values listed separately at the end:

Query: select "id", "category_id", "name", ... from "items" where "items"."category_id" = $1 order by "items"."id" -- params: [1]

See the $1? Drizzle never glues your values into the SQL text. It sends the SQL with numbered blanks, and the values separately, as parameters. Keep that in mind for 11d.

11b. The route reads the parameter

Everything after the ? in an address is the query string: named values, joined with &. In a route, read them like this (you saw it in week 11's "Going further"):

// ?search=lat -- text, and it can be missing.
const query = new URL(request.url).searchParams;
const search = query.get("search") ?? "";

query.get("search") gives "lat", or null if there's no search in the address. ?? "" turns that null into an empty string. Pass search to getCoffees(search). You can delete the Steps 11 and 12 TODO now.

11c. The service uses it

Give getCoffees a search: string input, add ilike to the drizzle-orm import, and add a second rule next to isCoffee:

.where(and(isCoffee, ilike(items.name, `%${search}%`)))

That's the SQL name ILIKE '%lat%'. LIKE matches a pattern, where % means "any characters, or none," so %lat% is "lat anywhere in the name." The I in ILIKE means it ignores capital letters. And an empty search, %%, matches every name, which is why "no search" still lists everything.

The teaching point: parameters, not pasted text

' OR 1=1 -- is the oldest attack on a database. If code built the SQL by pasting text together, the query would become ... WHERE name ILIKE '%' OR 1=1 --%': the quote ends the text early, OR 1=1 is true for every row, and -- turns the rest into a comment. On a login form, that's how people get in without a password. It's called SQL injection.

Look at your terminal:

... where ("items"."category_id" = $1 and "items"."name" ilike $2) ... -- params: [1, "%' OR 1=1 --%"]

The SQL is exactly the same shape as for latte. The attack arrived as a value in $2, and Postgres went looking for a coffee with that odd name. There isn't one. Because every query goes through Drizzle, and every query lives in the service, there's no place in this app where someone's text gets pasted into SQL.

  • The wrong database. Neon's Connect box starts on neondb. The string connects fine, so the pull says 1 tables fetched or 0, and a route says relation "items" does not exist. Check the end of the string first.
  • After a wrong pull, delete drizzle/. Pulling again rewrites schema.ts, but leaves the first pull's 0000_...sql and meta/ behind, still describing the wrong database.
  • Every pull erases your edit. mode: "number" is gone, and the page crashes with toFixed is not a function. Redo it after every pull; the list in README.md is there so you don't have to remember.
  • Restart after changing .env.local. Next only reads it when it starts. drizzle-kit reads it every time you run it.
  • The pull needs Node 22 or newer. Check with node --version.
  • Counting ../. Three from app/api/coffees/route.ts, four from app/api/coffees/[id]/route.ts, one from services/itemService.ts. A red underline on the import line is the tell; the error says Module not found.
  • A forgotten await sends {}, and the list says "No coffees found." with no error anywhere.
  • A 500 with no message on the page means something threw. The terminal has the reason, down to the line, usually with a [cause]: from Postgres. Read it before you change anything.
  • Your changes are real now. Every create, edit and delete stays in your database, and the expected results in later steps assume you did the earlier ones. If your store gets into a strange state, run db/0001_store.sql again in the SQL Editor on store; everything goes back to the way it started.

C3 · The Neon provider

// The ONE file that knows how to reach the database.
// A provider wraps something outside our app: here, Neon.
import { neon } from "@neondatabase/serverless";
import { drizzle, type NeonHttpDatabase } from "drizzle-orm/neon-http";

export class NeonDatabaseProvider {
  // One copy for the whole app, made the first time somebody asks.
  private static instance: NeonDatabaseProvider;
  private db: NeonHttpDatabase | undefined;

  public static getInstance(): NeonDatabaseProvider {
    if (!NeonDatabaseProvider.instance) {
      NeonDatabaseProvider.instance = new NeonDatabaseProvider();
    }
    return NeonDatabaseProvider.instance;
  }

  public getDb(): NeonHttpDatabase {
    if (!this.db) {
      // If the secret is missing, say so in plain words here,
      // instead of failing somewhere weird later.
      const url = process.env.NEON_DATABASE_URL;
      if (!url) {
        throw new Error(
          "NEON_DATABASE_URL is not set. Copy .env.example to .env.local and fill it in."
        );
      }
      this.db = drizzle(neon(url));
    }
    return this.db;
  }
}

export async function POST(request: Request) {
  let body;
  try {
    body = await request.json();
  } catch {
    return Response.json({ error: "The body must be JSON" }, { status: 400 });
  }

  if (body === null || typeof body !== "object") {
    return Response.json(
      { error: "The body must be a JSON object with name, description and price" },
      { status: 400 }
    );
  }
  if (typeof body.name !== "string" || body.name === "") {
    return Response.json({ error: "name is required" }, { status: 400 });
  }
  // description is optional: leave it out, or send "", and the coffee has none.
  if (body.description !== undefined && typeof body.description !== "string") {
    return Response.json({ error: "description must be text" }, { status: 400 });
  }
  if (typeof body.price !== "number" || body.price <= 0) {
    return Response.json({ error: "price must be a number above 0" }, { status: 400 });
  }

  const coffee = await ItemService.getInstance().createCoffee({
    name: body.name,
    description: body.description || null, // no description is NULL, like store.sql
    price: body.price,
    isAvailable: true, // a new coffee starts on sale
  });
  return Response.json(coffee, { status: 201 });
}

// The ONE file that knows how to ask the database about items.
// Routes call these methods. Routes never write a query themselves.
import { and, eq, ilike, lte } from "drizzle-orm";
import { NeonDatabaseProvider } from "../providers/neon/neonDatabaseProvider";
import { items, receiptItems } from "../drizzle/schema";

// Coffee is category 1 in store.sql. This app only ever works on coffees,
// so every query below uses this rule, written once.
const coffeeCategoryId = 1;
const isCoffee = eq(items.categoryId, coffeeCategoryId);

// What a route hands over to add or change a coffee. The route checks it first.
export type CoffeeInput = {
  name: string;
  description: string | null;
  price: number;
  isAvailable: boolean;
};

export class ItemService {
  private static instance: ItemService;

  public static getInstance(): ItemService {
    if (!ItemService.instance) {
      ItemService.instance = new ItemService();
    }
    return ItemService.instance;
  }

  private getDb() {
    return NeonDatabaseProvider.getInstance().getDb();
  }

  // search "" matches every name. maxPrice is optional: and() skips anything
  // that's undefined, so with no maxPrice there's simply no price rule.
  public async getCoffees(search: string, maxPrice?: number) {
    return this.getDb()
      .select()
      .from(items)
      .where(
        and(
          isCoffee,
          ilike(items.name, `%${search}%`),
          maxPrice === undefined ? undefined : lte(items.price, maxPrice)
        )
      )
      .orderBy(items.id);
  }

  // Gives back undefined when there's no such coffee.
  public async getCoffee(id: number) {
    const [coffee] = await this.getDb()
      .select()
      .from(items)
      .where(and(eq(items.id, id), isCoffee));
    return coffee;
  }

  // .returning() hands back the row Postgres saved, new id included.
  // categoryId is added here, so a new coffee is always a coffee.
  public async createCoffee(input: CoffeeInput) {
    const [coffee] = await this.getDb()
      .insert(items)
      .values({ ...input, categoryId: coffeeCategoryId })
      .returning();
    return coffee;
  }

  // Gives back undefined when there's no such coffee.
  public async updateCoffee(id: number, input: CoffeeInput) {
    const [coffee] = await this.getDb()
      .update(items)
      .set(input)
      .where(and(eq(items.id, id), isCoffee))
      .returning();
    return coffee;
  }

  public async deleteCoffee(id: number) {
    await this.getDb().delete(items).where(and(eq(items.id, id), isCoffee));
  }

  // Tuesday's foreign key: receipt_items points at items, so Postgres refuses
  // to delete a coffee that's on an old receipt. Asking first lets the route
  // say why, instead of crashing.
  public async hasBeenSold(id: number) {
    const [line] = await this.getDb()
      .select()
      .from(receiptItems)
      .where(eq(receiptItems.itemId, id))
      .limit(1);
    return line !== undefined;
  }
}

export async function POST(request: Request) {
  let body;
  try {
    body = await request.json();
  } catch {
    return Response.json({ error: "The body must be JSON" }, { status: 400 });
  }

  if (body === null || typeof body !== "object") {
    return Response.json(
      { error: "The body must be a JSON object with name, description and price" },
      { status: 400 }
    );
  }
  if (typeof body.name !== "string" || body.name === "") {
    return Response.json({ error: "name is required" }, { status: 400 });
  }
  // description is optional: leave it out, or send "", and the coffee has none.
  if (body.description !== undefined && typeof body.description !== "string") {
    return Response.json({ error: "description must be text" }, { status: 400 });
  }
  if (typeof body.price !== "number" || body.price <= 0) {
    return Response.json({ error: "price must be a number above 0" }, { status: 400 });
  }

  const coffee = await ItemService.getInstance().createCoffee({
    name: body.name,
    description: body.description || null, // no description is NULL, like store.sql
    price: body.price,
    isAvailable: true, // a new coffee starts on sale
  });
  return Response.json(coffee, { status: 201 });
}

export async function PUT(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;

  let body;
  try {
    body = await request.json();
  } catch {
    return Response.json({ error: "The body must be JSON" }, { status: 400 });
  }

  // PUT replaces the whole coffee, so every field has to be there.
  if (body === null || typeof body !== "object") {
    return Response.json(
      { error: "The body must be a JSON object with name, description, price and isAvailable" },
      { status: 400 }
    );
  }
  if (typeof body.name !== "string" || body.name === "") {
    return Response.json({ error: "name is required" }, { status: 400 });
  }
  if (typeof body.description !== "string") {
    return Response.json({ error: "description must be text (send \"\" for none)" }, { status: 400 });
  }
  if (typeof body.price !== "number" || body.price <= 0) {
    return Response.json({ error: "price must be a number above 0" }, { status: 400 });
  }
  if (typeof body.isAvailable !== "boolean") {
    return Response.json({ error: "isAvailable must be true or false" }, { status: 400 });
  }

  const coffee = await ItemService.getInstance().updateCoffee(Number(id), {
    name: body.name,
    description: body.description || null, // no description is NULL, like store.sql
    price: body.price,
    isAvailable: body.isAvailable,
  });
  if (!coffee) {
    return Response.json({ error: `No coffee with id ${id}` }, { status: 404 });
  }
  return Response.json(coffee);
}

export async function DELETE(
  request: Request,
  { params }: { params: Promise<{ id: string }> }
) {
  const { id } = await params;
  const service = ItemService.getInstance();

  const coffee = await service.getCoffee(Number(id));
  if (!coffee) {
    return Response.json({ error: `No coffee with id ${id}` }, { status: 404 });
  }
  // 409 Conflict: the request is fine, but the data says no.
  if (await service.hasBeenSold(coffee.id)) {
    return Response.json(
      { error: `${coffee.name} is on old receipts, so it can't be deleted. Mark it sold out instead.` },
      { status: 409 }
    );
  }

  await service.deleteCoffee(coffee.id);
  return new Response(null, { status: 204 });
}

// The ONE file that knows how to reach the database.
// A provider wraps something outside our app: here, Neon.
import { neon } from "@neondatabase/serverless";
import { drizzle, type NeonHttpDatabase } from "drizzle-orm/neon-http";

export class NeonDatabaseProvider {
  // One copy for the whole app, made the first time somebody asks.
  private static instance: NeonDatabaseProvider;
  private db: NeonHttpDatabase | undefined;

  public static getInstance(): NeonDatabaseProvider {
    if (!NeonDatabaseProvider.instance) {
      NeonDatabaseProvider.instance = new NeonDatabaseProvider();
    }
    return NeonDatabaseProvider.instance;
  }

  public getDb(): NeonHttpDatabase {
    if (!this.db) {
      // If the secret is missing, say so in plain words here,
      // instead of failing somewhere weird later.
      const url = process.env.NEON_DATABASE_URL;
      if (!url) {
        throw new Error(
          "NEON_DATABASE_URL is not set. Copy .env.example to .env.local and fill it in."
        );
      }
      // logger: true prints every query and its params in the terminal (Step 11).
      this.db = drizzle(neon(url), { logger: true });
    }
    return this.db;
  }
}
