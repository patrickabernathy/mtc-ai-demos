What to make this page do

The HTML and CSS are finished. The file script.js is already connected at the bottom of this page, and it is empty. Everything below is your job.

First, prove the connection. Put console.log('connected'); in script.js, reload this page, and open the console (right-click → Inspect → Console). If you don't see the word connected, stop and fix that before writing anything else.

Action 1 — Required

Someone types their name and email and clicks Request appointment. A message appears in the empty box under the form that shows what they actually typed. Not a fixed sentence — their name has to be in it.

Action 2 — Required

Someone clicks Request appointment with the name or email box empty. Two things have to happen.

One: the same box says something useful instead — "We need a name and an email address" — not a blank space, and not nothing at all.

Two: mark the boxes that are actually wrong. A message at the bottom of a form doesn't tell anybody which field to go fix. So put the class is-invalid on each empty box: 

document.getElementById('name').classList.add('is-invalid');

Two things happen when you do — the box turns red, and a short red line of text appears under it. That text is already written and already in the HTML; it's hidden until the box next to it is marked invalid, so you get it for free.

Only mark the ones that are empty. If they typed a name but no email, the name box stays normal.

And take the class off again when they fix it. This is the half everybody forgets. Someone leaves the email blank, gets a red box, types their email, clicks again — and the box is still red, because nothing ever removed the class: 

document.getElementById('email').classList.remove('is-invalid');

Every time they click, every box should end up marked or unmarked based on what's in it right now — not on what was wrong last time. This bug is in real, shipped, paid-for software everywhere. Now you'll see it for the rest of your life.

Action 3 — Optional

After a successful request, empty the boxes so the next person can type in them, and include the day they chose in the message.

Where is-invalid comes from. It isn't a name we made up. It's Bootstrap's — the styling library the class has been using — and it is what Bootstrap forms use to mark a bad field everywhere in the world. This page doesn't load Bootstrap; the red box and the red text are written into styles.css by hand, using Bootstrap's name and Bootstrap's exact red so that what you learn here is what you'll type on a real Bootstrap form later. The partner class on the little red message is called invalid-feedback, also Bootstrap's.

Expect this one. You click the button and the whole page flashes, your typing vanishes, and it looks like nothing happened. That's the form doing its original job. Write it in your log before you go looking for the fix.
