2. Move the stylesheet over

You said yes to Tailwind, so src/app/globals.css already has Tailwind's own setup in it plus a few starter rules. We're not writing Tailwind classes tonight — we're bringing our own CSS, the same CSS you already have.

  1. Open src/app/globals.css.
  2. Keep the very first line, @import "tailwindcss";.
  3. Delete everything else in that file.
  4. Paste the entire contents of this lab's styles.css underneath it.

Nothing changes on screen yet, because page.tsx is still the Next starter. That's fine.

Expect this one. Tailwind quietly resets a lot of browser defaults — heading sizes, list bullets, paragraph margins. Our stylesheet sets all of that back on purpose, so the page should look right. But if something is mysteriously the wrong size and it isn't in styles.css, that's who did it. Inspect the element and look at what's crossed out.

3. Rebuild the page in JSX

Open index.html. Four numbers across the top, then three panels, each with a heading, sometimes a note under the heading, and a table of stock lines with a coloured status pill on each row.

Same first move as always: empty src/app/page.tsx and get the markup rendering in JSX before you refactor a single thing. class to className, close every tag, HTML comments become {/* */}.

Expect this one. This page has real <table>s in it. React is fussy about tables in a way the browser is not: if you write <table><tr> without a <tbody> around the rows, the browser silently fixes it and React yells at you in the console. The HTML already has <thead> and <tbody> in the right places — keep them.

Stop here and check. Page at localhost:3000 matches index.html exactly. Four stat cards, three panels, ten stock lines, pills in three different colours. Then start cutting.

4. The data, and a function that decides things

Required. Make src/types/order.ts. Start with the types: 

// src/types/order.ts

export type Tone = "ok" | "warn" | "late";

export type OrderLine = {
  item: string;
  onHand: number;
  par: number;
};

export type PanelData = {
  title: string;
  note?: string;      // not every panel has one
  lines: OrderLine[]; // an array, inside an object, inside an array
};

export type StatItem = {
  label: string;
  value: string;      // "10", "$1,842", "Tue" — not all of these are numbers
  hint?: string;
};

Look at OrderLine for a second. There's no status on it and no tone. That's deliberate. "Order tonight" isn't a fact about the item — it's a conclusion you draw from onHand and par. Storing it means two copies of the truth that can disagree, and eventually they will.

Required. So write the rule down once, as a function, in the same file: 

export type Status = {
  tone: Tone;
  label: string;
};

export function statusFor(line: OrderLine): Status {
  if (line.onHand < line.par / 2) return { tone: "late", label: "Order tonight" };
  if (line.onHand < line.par)     return { tone: "warn", label: "Getting low" };
  return { tone: "ok", label: "Fine" };
}

The return type Status is doing real work there. Try returning { tone: "urgent", label: "..." } from one branch and see what TypeScript says. Then take the return type off entirely and notice that the error moves somewhere much less helpful. Put it back.

PanelData and StatItem, not Panel and Stat. You are about to write components called Panel and Stat, and a file that imports both the type and the component can't have two things called the same thing. Naming your way out of that collision now is cheaper than renaming six files later.

Badge — children, and a typed lookup

In lab 2 the badge worked out its own label. This one doesn't. It gets handed the text the way an HTML tag does — between its opening and closing tags: 

<Badge tone="late">Order tonight</Badge>

Anything you put between the tags of a component arrives as a prop called children. Its type is React.ReactNode — "any renderable thing": a string, a number, an element, a list of them.

Three tones means three class names, and a chain of ternaries gets ugly fast at three. Use a lookup object instead, and type it so it can't be incomplete: 

// src/components/Badge.tsx

import type { Tone } from "@/types/order";

const toneClass: Record<Tone, string> = {
  ok: "tone-ok",
  warn: "tone-warn",
  late: "tone-late",
};

type BadgeProps = {
  tone: Tone;
  children: React.ReactNode;
};

export function Badge({ tone, children }: BadgeProps) {
  return <span className={`badge ${toneClass[tone]}`}>{children}</span>;
}

Worth ten seconds. Delete the late: line from toneClass. Record<Tone, string> means "a key for every Tone, no exceptions" — so TypeScript fails immediately, pointing at the object, not at some blank badge you'd have found on Thursday. Put it back, then add a fourth tone to the Tone union and watch it fail from the other direction.

Panel — a component that holds other components

Panel is the interesting one. It draws the box, the heading, and the optional note — and then it renders whatever it was given, without knowing or caring what that is: 

// src/components/Panel.tsx

type PanelProps = {
  title: string;
  note?: string;
  children: React.ReactNode;
};

export function Panel({ title, note, children }: PanelProps) {
  return (
    <section className="panel">
      <div className="panel-head">
        <h2>{title}</h2>
        {note && <p className="panel-note">{note}</p>}
      </div>
      {children}
    </section>
  );
}

{note && <p ...>} is how you render something conditionally. If note is missing, the whole expression is undefined and React draws nothing — no empty <p>, no stray margin. The "Shelf" panel has no note; check in the inspector that there is genuinely no paragraph tag there.

Expect this one, eventually. {count && ...} with a number that happens to be 0 renders a literal 0 on the page, because 0 is falsy but still renderable. It doesn't bite you tonight — note is a string — but it will, and when a mysterious 0 shows up in your layout you'll know why.

Then page.tsx is just the arrangement

export default function Home() {
  return (
    <div>
      <Header />
      <main>
        <StatRow stats={stats} />
        {panels.map((panel) => (
          <Panel key={panel.title} title={panel.title} note={panel.note}>
            <LineTable lines={panel.lines} />
          </Panel>
        ))}
      </main>
      <Footer />
    </div>
  );
}

Read that and notice what isn't in it. No item names. No numbers. No class names except the ones inside the components. It says what the page is made of, and every question about how any one piece looks is answered somewhere else. That's the whole idea, and it's the last time tonight anybody will say it to you.

6. The styling bit — a CSS Module for Stat

Everything so far shares one giant globals.css, which means every class name in the app is competing for the same handful of words. Two people writing .card in the same project is a real Tuesday afternoon.

Required. Give Stat its own stylesheet instead. Make src/components/Stat.module.css — the .module.css in the name is what turns the feature on: 

/* src/components/Stat.module.css */

.stat {
  display: flex;
  flex-direction: column;
  gap: 2px;
  /* ...move the rest over from globals.css... */
}

.label { /* was .stat-label */ }
.value { /* was .stat-value */ }
.hint  { /* was .stat-hint  */ }

Use it like this:

// src/components/Stat.tsx

import styles from "./Stat.module.css";

export function Stat({ label, value, hint }: StatProps) {
  return (
    <li className={styles.stat}>
      <span className={styles.label}>{label}</span>
      {/* ...you finish it... */}
    </li>
  );
}

Then cut the four .stat* rules out of globals.css. Not copy — cut. If the page still looks right afterwards, the module is doing the work. If it breaks, it wasn't.

Leave .stats (the grid that holds them) in globals.css — that one belongs to StatRow, not to Stat. Deciding which rule belongs to which component is the actual skill here; the syntax takes four minutes.

Look at what it did. With the page rendering correctly, right-click a stat card and inspect it. The class isn't stat — it's something like Stat_stat__x7f2q. Next rewrote it at build time so it cannot possibly collide with anyone else's .stat. You wrote a short name; the tool guaranteed a unique one.

What "done" looks like

  • Panel takes children and doesn't know a table is inside it.
  • Stat is styled by Stat.module.css, and those rules are gone from globals.css.
